# Доступ к каналам — серверная часть (Google Apps Script)

Экран «Доступ к каналам» в мини-приложении показывает человеку его личный
список приватных каналов и даёт кнопку «Вступить». Ссылка не впускает сама —
она создаёт **заявку на вступление**, а решение принимает бот, сверившись с
листом `Access`.

Файлы в этой папке **добавляются** в существующий проект Apps Script рядом с
кодом, который принимает алерты TradingView. Логика сигналов не меняется:
всё новое живёт в своих файлах, а в ваш `doPost` добавляются четыре строки
(шаг 5), которые пропускают чужие запросы дальше без изменений.

| Файл | Зачем |
|---|---|
| `01_config.gs` | свойства скрипта, доступ к таблице, вызовы Telegram API |
| `02_initdata.gs` | проверка подписи `Telegram.WebApp.initData` |
| `03_miniapp_api.gs` | эндпоинт `getMyChannels` для мини-приложения |
| `04_join_request.gs` | ветка `chat_join_request`: одобрить или отклонить |
| `05_setup.gs` | разовые утилиты: листы, инвайт-ссылки, вебхук |

---

## Шаг 1. Отдельная приватная таблица

Создайте **новую** таблицу Google Sheets — не ту, из которой приложение читает
статистику.

Это не перестраховка. Приложение забирает статистику по публичной ссылке
gviz, без авторизации: id таблицы лежит прямо в `app.js`, и любой, кто откроет
исходник, прочитает **любой** лист этой таблицы. Положи мы туда `Access` и
`Channels` — наружу уехали бы telegram-id всех ваших клиентов и все
инвайт-ссылки разом. Новая таблица никому не раздаётся и остаётся приватной.

Скопируйте её id из адреса: `docs.google.com/spreadsheets/d/<ЭТО_ID>/edit`.

## Шаг 2. Свойства скрипта

В проекте Apps Script: **Настройки проекта → Свойства скрипта → Добавить**.

| Свойство | Значение |
|---|---|
| `BOT_TOKEN` | токен бота — тот же, которым рассылаются сигналы |
| `ACCESS_SHEET_ID` | id таблицы из шага 1 |
| `SUPPORT_URL` | *(необязательно)* ссылка, которую увидит человек при отказе |
| `TG_SECRET_TOKEN` | *(необязательно)* если на вебхуке **уже** стоит `secret_token` — положите его сюда, иначе переустановка вебхука его сбросит |

Токен в коде не хранится нигде.

## Шаг 3. Файлы и листы

1. Скопируйте пять `.gs`-файлов в проект (каждый — отдельным файлом).
2. Запустите `whoAmI()` — в логе должно появиться имя вашего бота. Если нет,
   неверный `BOT_TOKEN`, дальше идти незачем.
3. Запустите `setupSheets()` — в приватной таблице появятся четыре листа с
   заголовками. Уже заполненные листы функция не трогает.

**Channels** — один канал на строку:

| столбец | что писать |
|---|---|
| `key` | короткий код: `main`, `pro10`, `vip`. По нему выдаются права |
| `title_ru` / `title_en` / `title_uk` | название на экране |
| `description_ru` / `_en` / `_uk` | строчка под названием |
| `chat_id` | id канала, вида `-1001234567890` |
| `join_link` | **оставьте пустым** — заполнит шаг 4 |
| `tier` | тариф: `pro`, `vip`… Значение `free` (или `public`, `all`) = канал открыт всем без строки в `Access` — так настраивается основной канал |
| `sort_order` | порядок на экране, число |
| `active` | `FALSE` прячет строку. Пусто = показывать |

**Access** — кому что можно:

| столбец | что писать |
|---|---|
| `user_id` | telegram-id человека |
| `username` | для вашего удобства, в логике не участвует |
| `channel_keys` | `*` = всё; либо список кодов: `pro10, pro30` |
| `tier` | вместо списка кодов: `pro` откроет все каналы с этим тарифом |
| `note`, `updated_at` | ваши пометки |

Строк на одного человека может быть несколько — права складываются.
Это удобнее, чем править одну длинную ячейку при каждой докупке.

**Folders** — `tier` и `folder_link` (ссылка `t.me/addlist/…`). Отдаётся
кнопкой «Добавить все каналы одной папкой». Строка с `tier` = `*` подойдёт
любому, у кого вообще есть доступ.

**JoinLog** — заполняется сам, руками туда писать не нужно.

## Шаг 4. Бот — админ, ссылки — в таблицу

1. В **каждом** канале из `Channels` сделайте бота администратором с правом
   **«Пригласительные ссылки»** (`can_invite_users`). Без него бот не сможет
   ни выпустить ссылку, ни одобрить заявку.
2. Запустите `setupInviteLinks()`. Для строк с пустым `join_link` она создаст
   ссылку с `creates_join_request = true` и запишет её в лист. Строки, где
   ссылка уже есть, функция не трогает — перевыпуск сломал бы ссылки,
   которые успели разойтись по людям.
3. В логе проверьте список «НЕ УДАЛОСЬ»: почти всегда это неверный `chat_id`
   или бот не админ.

## Шаг 5. Четыре строки в ваш `doPost`

Откройте файл с существующим `doPost` и добавьте **в самое начало** тела:

```js
function doPost(e) {
  // --- доступ к каналам: запрос из мини-приложения ---
  var mini = miniAppTryHandle_(e);
  if (mini) return mini;

  // --- доступ к каналам: заявка на вступление ---
  var join = tgJoinTryHandle_(e);
  if (join) return join;

  // ... дальше ваш существующий код сигналов, без единого изменения ...
}
```

Обе функции возвращают `null`, если запрос не их: тело не разбирается как
JSON с полем `action` из белого списка и не содержит `chat_join_request`.
Алерты TradingView — хоть текстом, хоть JSON — проходят насквозь.

**Почему не отдельный `doPost` в новом файле:** в Apps Script все файлы живут
в одном пространстве имён, и второе объявление `doPost` молча затирает первое.
Это ровно тот способ сломать приём сигналов, которого мы избегаем.

## Шаг 6. Развернуть новую версию

**Развёртывание → Управление развёртываниями → ✏️ → Версия: «Новая версия» →
Развернуть.**

Важно: правьте **существующее** развёртывание, не создавайте новое. У нового
будет другой адрес `/exec`, и TradingView продолжит слать алерты на старый.

Параметры должны остаться: «Запускать от имени: **я**», «У кого есть доступ:
**все**». Адрес `/exec` при правке версии не меняется.

## Шаг 7. Вебхук: добавить `chat_join_request`, ничего не потеряв

1. Запустите `webhookInfo()`. В логе будет подсказка:
   * `allowed_updates` **не задан** — действует подписка по умолчанию, а
     `chat_join_request` в неё уже входит. **Трогать вебхук не нужно,
     переходите к шагу 8.**
   * `chat_join_request` уже в списке — тоже ничего не нужно.
   * иначе — пункты 2–3.
2. `webhookCheckJoinRequests()` — проверка, ничего не отправляет. В логе
   напечатано «Было / Будет»; убедитесь, что в «Будет» остались **все**
   прежние типы и добавился один новый.
3. `webhookApplyJoinRequests()` — применить. Затем снова `webhookInfo()`.

Функция намеренно не собирает список с нуля: `setWebhook` перезаписывает
`allowed_updates` целиком, и отправить туда один `chat_join_request` значит
отписаться от всего остального.

Если в логе предупреждение про `TG_SECRET_TOKEN` — прочтите его. Telegram не
отдаёт текущий `secret_token` через `getWebhookInfo`, поэтому переустановка
вебхука его сбрасывает, если вы не положили его в свойства скрипта.

## Шаг 8. Включить экран в приложении

В `app.js` найдите:

```js
const CHAN_API = '';
```

и впишите адрес `/exec` вашего развёртывания. Закоммитьте и выложите на
GitHub Pages. До этого момента экран уже работает — показывает карточку
основного канала и подпись, что список подключается.

## Почему адрес `/exec` публичный и что с этим делать

Веб-приложение Apps Script доступно всем, у кого есть ссылка, и заголовки
запроса коду недоступны — значит, проверить `secret_token` от Telegram
нельзя. Практический риск небольшой: одобрить заявку можно только ту, которая
действительно существует, и только человеку со строкой в `Access`; подделкой
апдейта чужой доступ не получить. Но чужой запрос может засорить `JoinLog`
или отклонить чью-то живую заявку.

Если хотите закрыть и это:

1. `setupHookSecret()` — сгенерирует и запишет `TG_HOOK_QS`.
2. `webhookCheckJoinRequests()`, затем `webhookApplyJoinRequests()` — секрет
   допишется в адрес вебхука как `?s=…`, а `allowed_updates` при этом
   сохранятся.

После этого заявки без верного `s` игнорируются молча. На запросы
мини-приложения и на алерты TradingView это не влияет: проверка стоит только
в ветке заявок.

## Тестовый сценарий

1. **Проверка подписи.** Откройте мини-приложение, в консоли скопируйте
   `Telegram.WebApp.initData`, вставьте в `testInitData()` в `02_initdata.gs`
   и запустите. В логе должен появиться ваш `user.id`.
2. **Своя строка в `Access`.** Добавьте строку: `user_id` = ваш id,
   `channel_keys` = `*`.
3. **Экран.** Откройте «Доступ к каналам». Ожидаемо: все активные каналы,
   у тех, где вы уже состоите, — зелёная метка «Вы в канале», у остальных —
   кнопка «Вступить». Счётчик сверху показывает «Доступно вам: N из N».
4. **Вступление.** Возьмите канал, где вас нет, нажмите «Вступить». Telegram
   откроет канал с кнопкой «Подать заявку». Подайте.
5. **Журнал.** В листе `JoinLog` должна появиться строка: время, ваш id,
   username, `chat_id`, `channel_key`, `decision` = `approved`.
   Вступление происходит за секунды.
6. **Проверка отказа.** Замените в своей строке `Access` `*` на список без
   одного канала, подождите минуту (кеш) и откройте экран заново — этот канал
   станет с замком. Если подать заявку в него напрямую по старой ссылке, бот
   её отклонит, пришлёт в личку объяснение, а в `JoinLog` появится
   `declined`.
7. **Сигналы.** Дождитесь ближайшего алерта TradingView и убедитесь, что он
   пришёл в канал как обычно. Это главная проверка: ветки выше не должны были
   его задеть.

Если на шаге 5 строки нет — проверьте по порядку: бот админ в канале;
`chat_id` в `Channels` совпадает с каналом; `webhookInfo()` показывает
`chat_join_request`; в **Выполнениях** проекта нет ошибок.

---

## Что этот код НЕ делает

* **Не отзывает доступ.** Кто вступил — остаётся в канале навсегда. Удаление
  строки из `Access` закрывает только новые заявки.
* **Не трогает приём и рассылку сигналов.** Ни одна функция здесь не читает
  и не пишет рабочую таблицу статистики.
* **Не перевыпускает уже выданные инвайт-ссылки.**
