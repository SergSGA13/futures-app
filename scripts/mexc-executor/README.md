# MEXC Event Futures Executor

Исполнитель ставок на событийных фьючерсах MEXC. Принимает MEXC-хук из
`tv_webhook_v3.9.6.gs` и нажимает Up/Down на веб-странице
`mexc.com/futures/event-futures/<SYMBOL>` через Playwright.

## Зачем это, если фильтры уже есть

Фильтр payout (FM, порог 80%) и монитор payout уже работают в Apps Script.
Здесь закрывается последний ручной шаг — сам клик. Слот под это в конфиге
Apps Script уже предусмотрен:

```js
MEXC: {
  WEBHOOK_URL: "https://<ваш-хост>/bet/<EXECUTOR_SECRET>",
  WEBHOOK_ENABLED: true,   // было false
}
```

Хук уходит только для сигналов ветки MEXC со `status === "sent"`, то есть
F4/F5/F7/F8/FM уже отработали. Исполнитель их **не повторяет** — он проверяет
только то, чего вебхук знать не может (см. ниже).

## Что проверяется перед реальной ставкой

| Предохранитель | Зачем |
|---|---|
| Возраст сигнала (`maxSignalAgeSec`, 45с) | На 10-минутном горизонте сигнал трёхминутной давности — уже другая ситуация. Проверяется дважды: на входе и **перед самым кликом**, потому что задание могло ждать очереди. |
| Живой payout перед кликом | За время доставки payout мог упасть с 80% до 70%. FM в Apps Script читает кэш, здесь — актуальное значение. Единственная причина отказа, о которой приходит алерт в Telegram. |
| Дедупликация | Ретрай Apps Script или дубль потока не должен стать второй ставкой. |
| Кап 5 ставок / 11 минут | Дублирует F8, но по **фактически размещённым**. В Apps Script стейты веток раздельные, суммарно они могут выпустить больше 5 — а лимит биржи один. |
| Очередь по одной ставке | Браузер один; параллельные клики ломают форму суммы. |
| Пауза | `POST /pause/<secret>` — стоп без перезапуска. |

Кап и дедуп живут в памяти процесса: после рестарта счётчик слотов пустой.
Перезапускайте на паузе или в спокойный момент, а не посреди пачки сигналов.

## Установка

```bash
cd scripts/mexc-executor
npm install
cp config.example.json config.json    # задайте secret
npm run login                          # разовый вход в MEXC, сессия ляжет в профиль
npm test                               # 25 проверок, биржа не нужна
npm start
```

`npm run login` открывает окно браузера: логинитесь руками (включая 2FA) и
жмёте Enter. Пароль нигде не хранится — в профиле только куки.

## Порядок запуска в бой

Не включайте боевой режим сразу. Разумная последовательность:

1. **`dryRun: true`** (по умолчанию). Исполнитель делает всё, кроме финального
   клика, и пишет `executor_log.csv`. Дайте поработать день.
2. Смотрите в логе колонку `latencyMs` — это задержка от прихода сигнала в
   Apps Script до готовности ставки. Если она регулярно больше 10-15 секунд,
   ставить по таким сигналам смысла мало, надо разбираться с доставкой.
3. Смотрите `payoutLive` против `payoutHook`: расхождение показывает, как часто
   payout падает уже после того, как FM пропустил сигнал.
4. Только потом `dryRun: false` и **маленькая ставка** (5-10 USDT), а не 125.
   Убедитесь на живых деньгах, что позиции реально открываются в нужную
   сторону, и лишь затем поднимайте размер.

## Настройки

| Ключ | Смысл |
|---|---|
| `secret` | Токен в URL хука. Длинная случайная строка. |
| `dryRun` | `true` — без кликов. Начинайте только с него. |
| `headless` | `false` — видно окно браузера. Для первых прогонов удобнее. |
| `stakeUsdt` | Размер ставки. Максимум на бирже — 150. |
| `minPayoutPct` | Порог payout. Держите равным `CONFIG.MEXC.MIN_PAYOUT`. |
| `maxSignalAgeSec` | Предельный возраст сигнала. |
| `ui.*` | Тексты интерфейса MEXC. При смене локали правится здесь, код не трогается. |

## Диагностика

```bash
npm run monitor                # история payout в CSV, браузер не нужен
curl localhost:8787/status     # режим, счётчики, занятые слоты
```

`monitor.js` полезен ещё и как проверка доступности REST-эндпоинта с вашего
сервера: у Apps Script и вашей машины разные IP и лимиты.

## Риски, которые надо понимать

Автоматизация веб-интерфейса — не то же самое, что официальный API. MEXC не
предоставляет API для событийных фьючерсов (в документации есть только
WebSocket-канал с **данными**), поэтому клик по странице остаётся единственным
способом. Отсюда два следствия:

- **Вёрстка может измениться в любой момент.** Тогда селекторы перестанут
  находить кнопки, и ставки просто не будут проходить (в лог пойдёт `error`).
  Поэтому алерты в Telegram включены на ошибки — молчаливый отказ хуже.
- **Правила биржи.** Автоматизация веб-клиента формально не то, для чего он
  предназначен. Риск претензий к аккаунту существует; решение за вами.

Обе причины — довод за то, чтобы держать ставку умеренной и следить за логом,
а не оставлять систему без присмотра на неделю.
