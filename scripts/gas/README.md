# Доступ к каналам — серверная часть (Google Apps Script)

Экран «Доступ к каналам» в мини-приложении показывает человеку его личный
список приватных каналов и даёт кнопку «Вступить». Ссылка не впускает сама —
она создаёт **заявку на вступление**, а решение принимает бот, сверившись с
листом `Access`.

Код добавляется в **существующий** проект Apps Script рядом с тем, что
принимает алерты TradingView. Логика сигналов не меняется: всё новое живёт в
своих функциях, а в ваш `doPost` добавляются четыре строки (шаг 5).

---

# Быстрый путь — 6 шагов

Всё, что можно было сложить в одну кнопку, сложено в `install()`. Она
проверяет токен, заводит листы, сверяет права бота в каждом канале, выпускает
недостающие инвайт-ссылки, смотрит вебхук — и печатает список того, что
осталось сделать руками. Запускать её можно сколько угодно раз: готовое она
не переделывает, выданные ссылки не перевыпускает.

### 1. Вставить код

Один новый файл в проекте Apps Script, содержимое — из **`ALL_IN_ONE.gs`**.
Больше ничего копировать не нужно (остальные `.gs` в этой папке — исходники,
из которых он собран).

### 2. Два свойства скрипта

**Настройки проекта → Свойства скрипта → Добавить:**

| Свойство | Значение |
|---|---|
| `BOT_TOKEN` | токен бота — тот же, которым рассылаются сигналы |
| `ACCESS_SHEET_ID` | id приватной таблицы доступа (из её адресной строки) |

Токен нигде в коде не хранится.

Необязательные, но полезные: `SUPPORT_URL` — ссылка, которую увидит человек
при отказе; `TG_SECRET_TOKEN` — если на вебхуке **уже** стоит `secret_token`,
положите его сюда, иначе переустановка вебхука его сбросит.

### 3. Заполнить Channels и сделать бота админом

По строке на канал. Самое долгое — `chat_id`: их не нужно искать, они уже
есть в вашем коде рассылки сигналов, там каналы адресуются именно по ним.

`join_link` **оставьте пустым** — заполнит шаг 4.

В каждом канале сделайте бота администратором с правом **«Пригласительные
ссылки»** (`can_invite_users`). Без него бот не сможет ни выпустить ссылку,
ни одобрить заявку.

### 4. Запустить `install()`

В логе будет отчёт по каждому каналу и два раздела в конце: что сломано и что
осталось. Разберите «ПРОБЛЕМЫ ПО КАНАЛАМ» и запустите `install()` ещё раз —
пока список не опустеет.

Если в разделе «осталось» написано про вебхук — выполните там же
`webhookCheckJoinRequests()`, посмотрите строки «Было / Будет», затем
`webhookApplyJoinRequests()`. Чаще всего этого не требуется: когда
`allowed_updates` не задан, `chat_join_request` уже приходит.

### 5. Четыре строки в `doPost` и новая версия

В файл с существующим `doPost`, **в самое начало тела**:

```js
function doPost(e) {
  // --- доступ к каналам: запрос из мини-приложения ---
  var mini = miniAppTryHandle_(e);
  if (mini) return mini;

  // --- доступ к каналам: заявка на вступление ---
  var join = tgJoinTryHandle_(e);
  if (join) return join;

  // ... дальше ваш существующий код сигналов, без единого изменения ...
}
```

Обе функции возвращают `null`, если запрос не их. Алерты TradingView — хоть
текстом, хоть JSON — проходят насквозь.

Затем: **Развёртывание → Управление развёртываниями → ✏️ → Версия: «Новая
версия» → Развернуть.** Правьте **существующее** развёртывание, не создавайте
новое: у нового будет другой адрес `/exec`, и TradingView продолжит слать
алерты на старый.

### 6. `checkDeployment()` → адрес в приложение

Функция отправляет один запрос на ваш же `/exec` и проверяет, что он дошёл до
новой ветки и что без подписи данные не отдаются. В логе она напечатает
готовую строку:

```js
const CHAN_API = 'https://script.google.com/macros/s/.../exec';
```

Её нужно подставить в `app.js` вместо пустой, закоммитить и выложить на
GitHub Pages. До этого момента экран уже работает — показывает карточку
основного канала и подпись, что список подключается.

# Справочник

## Почему таблица доступа — отдельная

Приложение забирает статистику по публичной ссылке gviz, без авторизации: id
таблицы лежит прямо в `app.js`. Эта таблица открыта на чтение **кому угодно**
(в правах доступа стоит «Все, у кого есть ссылка»), а значит открыт и любой
лист в ней. Положи мы туда `Access` и `Channels` — наружу уехали бы
telegram-id всех клиентов и все инвайт-ссылки разом.

Таблица доступа создаётся отдельно и никому не раздаётся.

## Листы

**Channels** — один канал на строку:

| столбец | что писать |
|---|---|
| `key` | короткий код: `main`, `pro10`, `vip`. По нему выдаются права |
| `title_ru` / `title_en` / `title_uk` | название на экране |
| `description_ru` / `_en` / `_uk` | строчка под названием |
| `chat_id` | id канала, вида `-1001234567890` |
| `join_link` | заполняет `install()` |
| `tier` | тариф: `pro`, `vip`… Значение `free` (или `public`, `all`) = канал открыт всем без строки в `Access` — так настроен основной канал |
| `sort_order` | порядок на экране, число |
| `active` | `FALSE` прячет строку. Пусто = показывать |

**Access** — кому что можно:

| столбец | что писать |
|---|---|
| `user_id` | telegram-id человека |
| `username` | для вашего удобства, в логике не участвует |
| `channel_keys` | `*` = всё; либо список кодов: `pro10, pro30` |
| `tier` | вместо списка кодов: `pro` откроет все каналы с этим тарифом |
| `note`, `updated_at` | ваши пометки |

Строк на одного человека может быть несколько — права складываются. Это
удобнее, чем править одну длинную ячейку при каждой докупке.

**Folders** — `tier` и `folder_link` (ссылка `t.me/addlist/…`). Отдаётся
кнопкой «Добавить все каналы одной папкой». Строка с `tier` = `*` подойдёт
любому, у кого вообще есть доступ.

**JoinLog** — заполняется сам.

## Все функции

| Функция | Что делает |
|---|---|
| `install()` | всё из шага 4; запускать повторно безопасно |
| `checkDeployment()` | проверка после развёртывания, печатает строку для `CHAN_API` |
| `whoAmI()` | проверка токена: имя бота в лог |
| `setupSheets()` | только листы с заголовками |
| `setupInviteLinks()` | только выпуск недостающих ссылок |
| `webhookInfo()` | состояние вебхука и нужно ли что-то менять |
| `webhookCheckJoinRequests()` | показывает «Было / Будет», ничего не меняет |
| `webhookApplyJoinRequests()` | применяет изменение вебхука |
| `setupHookSecret()` | секрет для query-строки вебхука (см. ниже) |
| `testInitData()` | разовая проверка подписи на вашей строке `initData` |

## Про вебхук

`setWebhook` перезаписывает `allowed_updates` целиком — отправить туда один
`chat_join_request` значит отписаться от всего остального и оборвать приём
апдейтов, на которых живёт бот. Поэтому функции здесь не собирают список с
нуля, а добавляют один тип к существующим.

Вторая ловушка: `getWebhookInfo` **не** возвращает `secret_token`. Если он у
вас стоит и не положен в `TG_SECRET_TOKEN`, переустановка вебхука его
сбросит.

## Почему адрес `/exec` публичный и что с этим делать

Веб-приложение Apps Script доступно всем, у кого есть ссылка, а заголовки
запроса коду недоступны — значит, проверить `secret_token` от Telegram
нельзя. Практический риск небольшой: одобрить заявку можно только ту, которая
действительно существует, и только человеку со строкой в `Access`; подделкой
апдейта чужой доступ не получить. Но чужой запрос может засорить `JoinLog`
или отклонить чью-то живую заявку.

Если хотите закрыть и это: `setupHookSecret()`, затем
`webhookCheckJoinRequests()` и `webhookApplyJoinRequests()` — секрет
допишется в адрес вебхука как `?s=…`, а `allowed_updates` сохранятся. После
этого заявки без верного `s` игнорируются молча. На запросы мини-приложения и
на алерты TradingView это не влияет.

# Тестовый сценарий

1. **Проверка подписи.** Откройте мини-приложение, в консоли скопируйте
   `Telegram.WebApp.initData`, вставьте в `testInitData()` и запустите. В логе
   должен появиться ваш `user.id`.
2. **Своя строка в `Access`.** `user_id` = ваш id, `channel_keys` = `*`.
3. **Экран.** Откройте «Доступ к каналам». Ожидаемо: все активные каналы,
   у тех, где вы уже состоите, — зелёная метка «Вы в канале», у остальных —
   кнопка «Вступить». Сверху «Доступно вам: N из N».
4. **Вступление.** Возьмите канал, где вас нет, нажмите «Вступить». Telegram
   откроет канал с кнопкой «Подать заявку». Подайте.
5. **Журнал.** В `JoinLog` появится строка: время, ваш id, username,
   `chat_id`, `channel_key`, `decision` = `approved`. Вступление занимает
   секунды.
6. **Проверка отказа.** Замените в своей строке `Access` `*` на список без
   одного канала, подождите минуту (кеш) и откройте экран заново — этот канал
   станет с замком. Если подать заявку в него по старой ссылке, бот её
   отклонит, пришлёт в личку объяснение, а в `JoinLog` появится `declined`.
7. **Сигналы.** Дождитесь ближайшего алерта TradingView и убедитесь, что он
   пришёл в канал как обычно. Это главная проверка: ветки выше не должны были
   его задеть.

Если на шаге 5 строки нет — запустите `install()`, он назовёт причину.

# Что этот код НЕ делает

* **Не отзывает доступ.** Кто вступил — остаётся в канале навсегда. Удаление
  строки из `Access` закрывает только новые заявки.
* **Не трогает приём и рассылку сигналов.** Ни одна функция здесь не читает и
  не пишет рабочую таблицу статистики.
* **Не перевыпускает уже выданные инвайт-ссылки.**
