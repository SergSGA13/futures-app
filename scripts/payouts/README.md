# Сборщик выплат (payout)

Раз в 5 минут снимает выплаты и пишет их в таблицу Signals Log, в три **новые**
вкладки:

- `PAYOUTS_LOG` — журнал. Одна строка — один замер одной комбинации;
- `PAYOUTS_NOW` — последний снимок по каждой комбинации, справа — состояние
  источников (OK / ошибка) на момент последнего прохода;
- `PAYOUTS_DAILY` — за каждый день (по Варшаве): **средняя**, минимальная и
  максимальная выплата и число замеров по каждой комбинации. Сегодняшние
  строки обновляются каждые 5 минут, прошедшие дни остаются как есть.

**MEXC не собирается вообще:** ни запросов к бирже, ни чтения листов
`MEXC_PAYOUT` / `MEXC30_PAYOUT`.

Колонки: `Время UTC | Время Варшава | Биржа | Сеть | Актив | Направление |
Экспирация | Выплата % | Источник | Примечание`.

**Выплата %** — чистая прибыль при выигрыше в процентах от ставки (82 значит
«ставка 100 → получить 182»).

Существующие листы (`TOOBIT_PAYOUT` только читается; `MEXC_PAYOUT`,
`ALLsignal` и др.) сборщик **не меняет**. Цепочку TradingView → Apps Script он
не затрагивает.

## Что откуда берётся

| Площадка | Откуда | Состояние |
|---|---|---|
| **Speed Market** (Thales/Overtime): Optimism, Arbitrum, Base | Прямо из контракта `SpeedMarketsAMM` через публичные узлы сетей (`eth_call`), без логина | Готово. Формула проверена по исходникам контракта. Живые данные ещё не проверены, см. ниже |
| **Toobit** (BTC, ETH, SOL, XRP) | Тот же запрос, которым страница event-futures получает список рынков: `GET https://bapi.toobit.com/bapi/v1/event/contract/symbol/list`, без входа. По каждой экспирации — `longPayRate` (UP) и `shortPayRate` (DOWN) | Готово. Запрос идёт с серверов Google, не с вашего IP |
| **ApeX** (BTC, ETH) | Выплата (`pp`) приходит странице только по WebSocket, обычного запроса нет | Отложено: Apps Script не умеет WebSocket. Возможный путь — отдельный новый Cloudflare Worker |
| **ByBit Odds** | — | Выключено. Публичного API нет |
| **MEXC** | — | Не собирается по вашему решению |

### Как считается выплата Speed Market

Так же, как в самом контракте:

```
игрок платит   ставка × (1 + safeBoxImpact + fee)
при выигрыше   2 × ставка
fee = комиссия LP по времени до экспирации
    + перекос (skew) по этому направлению
    − половина перекоса противоположного направления (если по своему перекоса нет)
skew = текущий риск / максимальный риск × maxSkewImpact

Выплата % = (2 / (1 + safeBoxImpact + fee) − 1) × 100
```

Все параметры читаются из контракта при каждом проходе: `lpFee`,
`timeThresholdsForFees`/`lpFees`, `safeBoxImpact`, `maxSkewImpact`,
`currentRiskPerAssetAndDirection`, `maxRiskPerAssetAndDirection`,
`supportedAsset`, `minimalTimeToMaturity`/`maximalTimeToMaturity`.

- Активы: по умолчанию ETH и BTC. Пишутся только те, что контракт
  отмечает как поддерживаемые.
- Экспирации: по умолчанию 1, 2, 5, 10, 15, 30, 60 минут. Те, что контракт
  не разрешает, отбрасываются.
- Если по направлению стоит нулевой лимит риска, оно считается закрытым и не
  пишется.
- Не учтено: бонус за ставку в токене площадки (если сайт его даёт) и
  проскальзывание. Возможная небольшая разница с сайтом — в последнем знаке.

Адреса контрактов взяты из публичного пакета `@thales-dao/contracts`
(`scripts/deployments.json`). Если Thales их сменит, новый адрес задаётся
свойством скрипта (см. ниже), код менять не нужно.

## Установка (5 минут)

1. Откройте таблицу Signals Log → **Расширения → Apps Script**. Если там уже
   есть ваш проект с вебхуками, **не вставляйте код в него**: создайте
   отдельный проект на <https://script.google.com> → «Новый проект».
2. Вставьте содержимое `Payouts.gs` в файл проекта и сохраните.
3. **Настройки проекта → Свойства скрипта → Добавить:**

   | Свойство | Значение |
   |---|---|
   | `PAYOUTS_SHEET_ID` | id таблицы Signals Log, часть адреса между `/d/` и `/edit` |

   Остальные свойства не обязательны, см. таблицу ниже.
4. Выберите функцию `payouts_testToobit` → **Выполнить**: печатает сырой
   ответ Toobit и разобранные выплаты. Затем `payouts_dryRun` и нажмите **Выполнить**. Google попросит
   разрешения: доступ к таблицам и к внешним адресам. В журнале появятся
   замеры, в таблицу ничего не пишется.
5. Выберите `payouts_install` → **Выполнить**. Ставятся два триггера
   (сбор раз в 5 минут, чистка раз в сутки в 3 часа), и сразу делается первый
   проход. Появятся вкладки `PAYOUTS_LOG` и `PAYOUTS_NOW`.

Остановить: `payouts_uninstall` (снимает только свои триггеры, данные
остаются).

## Настройки (свойства скрипта, все необязательные)

| Свойство | По умолчанию | Что делает |
|---|---|---|
| `PAYOUTS_WRITE_MODE` | `change` | `change`: строка пишется, когда выплата изменилась, и контрольная — раз в час. `all`: строка на каждый замер каждые 5 минут |
| `PAYOUTS_HEARTBEAT_MIN` | `60` | Для `change`: как часто писать строку без изменений |
| `PAYOUTS_KEEP_DAYS` | `14` | Сколько дней держать в `PAYOUTS_LOG` |
| `PAYOUTS_ARCHIVE_ID` | — | id **отдельной** таблицы-архива. Если задан, старые строки переносятся туда (вкладки по месяцам), иначе удаляются |
| `PAYOUTS_SOURCES` | `speed,toobit` | Какие источники включены. `monitor` — копия листа `TOOBIT_PAYOUT`, если нужна |
| `PAYOUTS_TOOBIT_ASSETS` | `BTC,ETH,SOL,XRP` | Активы Toobit |
| `PAYOUTS_SPEED_ASSETS` | `ETH,BTC` | Какие активы проверять на Speed Market |
| `PAYOUTS_MONITOR_TZ` | `Europe/Warsaw` | В каком поясе время `23.11 22:15` в листе монитора |
| `PAYOUTS_SPEED_EXPIRIES` | `1,2,5,10,15,30,60` | Экспирации Speed Market, минуты |
| `PAYOUTS_RPC_OPTIMISM` / `_ARBITRUM` / `_BASE` | публичные узлы | Свой RPC, если публичный начнёт отказывать. Адрес с ключом провайдера храните только здесь |
| `PAYOUTS_AMM_OPTIMISM` / `_ARBITRUM` / `_BASE` | из пакета Thales | Новый адрес контракта, если сменится |

## Надёжность

- **Ошибка одного источника не роняет остальные.** Каждый источник и каждая
  сеть обрабатываются отдельно, ошибка видна в `PAYOUTS_NOW` справа и в
  журнале выполнений Apps Script.
- **Пустые и ошибочные замеры не пишутся.** Нет числа, не разобрался ответ,
  выплата ≤ 0 или ≥ 1000 % — строка пропускается, а не пишется нулём.
- **Без дублей.** Одна комбинация пишется не чаще раза за 5-минутный слот.
  Запись монитора переносится один раз, по её собственному времени. Два
  прохода одновременно не идут (блокировка).
- **Устаревшее не выдаётся за свежее.** Запись монитора старше 30 минут не
  переносится, в состоянии будет пометка.

## Дневное среднее

`PAYOUTS_DAILY` считается по **каждому** 5-минутному замеру, независимо от
режима журнала. Поэтому в режиме `change` среднее не искажается тем, что в
журнал пишутся только изменения. Запись монитора Toobit идёт в среднее один
раз, по её собственному времени. День считается по Варшаве. Лист растёт
медленно: одна строка на комбинацию в день (≈ 30 строк в день).

## Рост листа

Примерный объём при всех трёх сетях Speed Market, 2 активах и 7 экспирациях
(84 комбинации) плюс MEXC:

| Режим | Строк в сутки | За 14 дней |
|---|---|---|
| `all` | ≈ 25 000 | ≈ 350 000 (≈ 3,5 млн ячеек) |
| `change` | от ≈ 2 000 (раз в час) до нескольких тысяч | ≈ 30–80 тыс. |

Лимит Google-таблицы — 10 млн ячеек на **всю** таблицу, вместе с остальными
листами. Поэтому по умолчанию стоит `change` и чистка старше 14 дней. Если
нужна полная история, задайте `PAYOUTS_ARCHIVE_ID`: отдельная таблица-архив
не нагружает рабочую.

## Как подключить Toobit / ApeX напрямую

Страницы бирж рисуются в браузере, и выплату они берут внутренним запросом.
Чтобы найти этот запрос, в редакторе Apps Script выполните:

```
payouts_discover('https://www.toobit.com/en-US/event-futures/ETH-SWAP-USDT')
payouts_discover('https://omni.apex.exchange')
```

(чтобы запустить с адресом, временно вставьте вызов в любую пустую функцию,
например `function t(){ payouts_discover('…') }`, и выполните `t`).

Запрос идёт **с серверов Google, не с вашего IP**, один раз, ничего не
сохраняется. В журнал печатаются найденные пути API со словами
event / predict / payout / odds. Пришлите этот журнал — по нему источник
подключается за один шаг.

## Проверка доступа с серверов Google

`payouts_probe('https://…')` печатает код ответа и начало ответа с серверов
Google. Удобно проверить, не режет ли биржа запросы Google, например
`payouts_probe('https://contract.mexc.com/api/v1/contract/ping')`.
